## 项目概述

AI安全审查系统是一个集成了多层安全检查的AI对话后端服务，旨在确保AI生成的内容符合相关规定和道德标准。

### 核心功能

- 🚪 **门卫模块**：对用户输入进行初步分类筛选
- 🔍 **政审模块**：识别涉政涉军敏感内容
- 🔤 **敏感词模块**：检测并处理敏感词汇
- ✅ **自审查模块**：对AI生成的回答进行安全审查
- 🧹 **数据净化模块**：对回答进行最终净化处理

## 快速开始

### 环境要求

- Python 3.9+
- GPU 服务器（用于 vLLM 推理）
- 基础模型和 LoRA 适配器

### 安装步骤

1. **克隆项目**
```bash
cd /path/to/project
```

2. **安装依赖**
```bash
pip install -r requirements.txt
```

3. **启动 vLLM 服务**（GPU 服务器）
```bash
python vllm_server.py
```

4. **启动后端服务**
```bash
# 开发模式
python main.py

# 生产模式
python run.py
```

5. **访问服务**
- 日志查看器：http://localhost:6006
- API 文档：http://localhost:6006/docs

## API接口

### 1. 聊天接口

**POST /chat**

完整的AI对话接口，返回详细的处理信息。

请求：
```json
{
    "text": "你好，请问今天天气怎么样？",
    "user_id": "user123",
    "model": null
}
```

响应：
```json
{
    "success": true,
    "message": "处理成功",
    "data": "你好！我无法获取实时天气信息，建议您查看天气预报应用。"
}
```

### 2. 简化聊天接口

**POST /v1/chat**

简化版接口，只返回数据字段。

请求：
```json
{
    "text": "你好"
}
```

响应：
```json
{
    "data": "你好！有什么我可以帮助你的吗？"
}
```

### 3. 健康检查

**GET /health**

响应：
```json
{
    "status": "healthy",
    "vllm_service": "healthy",
    "modules": ["doorkeeper", "political_review", "sensitive_words", "response", "self_review", "data_purification"]
}
```

### 4. 日志接口

- **GET /logs/history** - 获取历史日志
- **DELETE /logs/history** - 清空历史日志
- **GET /logs/snapshots** - 获取快照列表
- **POST /logs/save** - 保存日志快照
- **GET /logs/snapshot/{filename}** - 获取指定快照

## 安全模块详解

### 1. 门卫模块 (Doorkeeper)

**功能**：对用户输入进行初步分类，判断是否为恶意请求。

**处理流程**：
1. 调用 classify LoRA 进行分类
2. 调用外部 API 裁判进行二次判断
3. 双重裁判机制：双方一致才有效，否则放行

**分类结果**：
- `good` / `jailgood`：安全输入，放行
- 其他：可能的恶意输入

### 2. 政审模块 (Political Review)

**功能**：识别涉政涉军敏感内容，决定是否使用政治版模型。

**分类结果**：
- `Irrelevant`：非敏感领域，使用原版模型
- `Foreign`：明确指代外国，使用原版模型
- `China`：明确指代中国，使用政治版模型
- `Ambiguous`：指代不清，使用政治版模型

### 3. 敏感词模块 (Sensitive Words)

**功能**：检测用户输入中的敏感词汇。

**处理方式**：
- 检测到敏感词时，在用户输入前添加警告提示
- 不直接拒绝，而是提醒模型注意回答的合法性

### 4. 自审查模块 (Self Review)

**功能**：对 AI 生成的回答进行安全审查。

**评估标准**：
- `harmful=0`：回答可能有害，拒绝
- `harmful=1`：回答安全，通过

### 5. 数据净化模块 (Data Purification)

**功能**：对最终回答进行净化处理。

**处理内容**：
- 移除不当表述
- 确保语言规范礼貌
- 保持核心内容不变

## 部署指南

### AutoDL 平台部署

1. **GPU 实例配置**
   - 推荐：RTX 3090/4090 或 A100
   - 显存要求：24GB+

2. **模型准备**
   - 基础模型：Qwen2.5-7B-Instruct
   - LoRA 适配器：classify, china

3. **启动服务**
```bash
# 启动 vLLM 服务
nohup python vllm_server.py > vllm.log 2>&1 &

# 启动后端服务
nohup python run.py > app.log 2>&1 &
```

### Docker 部署（可选）

```dockerfile
FROM python:3.10-slim

WORKDIR /app
COPY . .

RUN pip install -r requirements.txt

EXPOSE 6006

CMD ["python", "run.py"]
```

## 常见问题

### Q1: vLLM 服务连接失败

**原因**：vLLM 服务未启动或端口配置错误

**解决**：
1. 确认 vLLM 服务已启动：`ps aux | grep vllm`
2. 检查端口配置是否一致
3. 查看 vLLM 日志排查错误

### Q2: 响应超时

**原因**：模型推理时间过长或网络延迟

**解决**：
1. 检查 GPU 负载
2. 适当增加超时配置
3. 优化模型推理参数

### Q3: 门卫模块误判

**原因**：分类模型或外部裁判判断不准确

**解决**：
1. 双重裁判机制会在意见不一致时自动放行
2. 可调整分类模型或裁判 API

### Q4: 敏感词检测不准确

**原因**：敏感词库覆盖不全

**解决**：
1. 更新敏感词库文件
2. 调整检测算法
